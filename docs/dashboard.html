What the numbers say

A second benchmark on the same nodes and the same energy counters as the training page: vLLM answering requests instead of a model being trained. Tokens per joule and samples per joule share no denominator and never belong in one table, which is why these are two pages rather than two sections. On NVIDIA, AIPerf measures its own power through pynvml; on Intel it can read nothing, and the energy comes from analysis/power_sidecar.py sampling the same hwmon counters the training runs use, from beside the run. Each machine's power traces and operating points are in its power profile; every curve, filterable, is above.

On polaris both instruments ran at once and agreed to within 0.3% across 12 levels — AIPerf's own NVML collector against the sidecar sampling the same GPUs. That is the only check the method gets: the Intel rows have no second instrument available, so their joules rest on this agreement holding somewhere it could be tested.

What the model costs (8 configurations at concurrency 32)

gemma-3-27b-it at TP=4 is the one pair here holding model, sharding and concurrency constant. polaris delivers 3.1× the tokens per joule of aurora — and drives each device 2.8× harder (131 W against 47 W), while finishing a token in 76 ms against 130 ms.

These are single-level runs, not sweeps — one concurrency each, so they carry no curve and no repeat. Read them as the cost of a model on a machine, not as a measurement of either machine's best. The vLLM versions still differ by machine, and every run is eager-mode.

Which machine serves more per joule — gemma-3-27b-it

At concurrency 32 and TP=4, the one configuration both machines swept: polaris delivers 3.1x the tokens per joule of aurora — but per joule of work, aurora is 1.59x ahead. The more efficient accelerator loses, because its node spends so much more simply being switched on.

Tokens per joule of node energy is what an allocation bills for; per joule of dynamic energy is node draw above the idle floor, measured on that node before its server started. The two rank the machines differently, which is the finding above. Prompt-shape sweeps are excluded — they hold concurrency fixed, so their spread is across prompts and not across load. Both measures against concurrency, for every machine and model, are on the inference dashboard as the tokens per joule and tokens per joule (dynamic) metrics. The machines did not run the same vLLM: versions are recorded in each sweep's run_meta.json, and both ran with --enforce-eager.

Which machine serves more per joule — Llama-3.1-8B-Instruct

At concurrency 32 and TP=1, the one configuration both machines swept: polaris delivers 4.3x the tokens per joule of aurora — but per joule of work, aurora is 1.32x ahead. The more efficient accelerator loses, because its node spends so much more simply being switched on.

Given each machine its best configuration (aurora at TP=8, polaris at TP=1), polaris leads on node energy by 2.8x, and aurora on dynamic energy by 1.32x. Filling a node changes the node-energy gap and not the dynamic one, because the idle draw is divided across more work rather than reduced.

What the terms mean

How much

Out tok/s
output tokens generated per second, all requests together
Conc
concurrent requests in flight; the swept variable
ISL / OSL
input and output sequence lengths, in tokens — pinned per row
TP
tensor parallelism: how many accelerators one model is sharded across

How fast

TTFT
time to first token — how long a request waits before anything comes back
ITL
inter-token latency — the gap between tokens once generation starts
Request latency
TTFT plus the whole generation, end to end
Prefill share
percent of request latency spent reading the prompt rather than writing

At what cost

Dyn W
dynamic power: node draw above the idle floor measured before the server started
Node power
watts drawn by every accelerator on the node, including ones this job left idle
Joules
total node energy over the level; comparable only between rows of equal request count
Tok/J
output tokens per joule of node energy — what an allocation bills for
Tok/J dyn
the same per joule of dynamic energy — what the silicon did
